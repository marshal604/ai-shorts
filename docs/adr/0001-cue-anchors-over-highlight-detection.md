# 以口令錨點取代亮點偵測，並分層降級

同類工具（AlphaCut、Opus Clip 及其開源仿作）都用 LLM 或視覺模型從整支長影片「猜」哪裡是重點，這在交易分析影片上失效——價值不在「講得好的話」，而在「講的話正對著的那張圖」，而畫面是無人臉的螢幕錄影，人臉追蹤與語意選段都抓不到。我們改為要求講者在錄影當下口頭標記事件，系統以字串比對定位，再把取材範圍限縮在錨點附近。但實測證明講者不會逐字照唸，所以口令是**快路而非唯一依據**：分三層逐級降級，口令命中就免費且決定性，漏喊則以弱訊號加 LLM 判定兜底。

## 分層偵測

| 層 | 職責 | 成本 | 性質 |
|---|---|---|---|
| **T1 前綴偵測** | 在正規化後的全文中找出前綴「這筆」的每一次出現 | 零 | 決定性，召回導向 |
| **T2 分類過濾** | LLM 讀每個候選的上下文，判定它是不是錨點、是哪一種事件 | 一次批次呼叫 | 以輸入雜湊快取，重跑不變 |

**偵測與分類分離，且只有偵測是字串比對。** 前綴負責召回（實測 100%），分類負責精確度。

分類不維護語音辨識變體的白名單。實測變體包括止盈→只贏／止音、止損→止存／簡體「损」，而且誤聽是情境相關的（同一位講者說「那這筆就是止盈」時 4/4 正確，說「TP1只贏了」時 2/2 錯誤）——人工白名單追不上，也無法預先窮舉。類別改為用**自然語言描述每種事件**，由 LLM 吸收變體。這同時讓新增類別不必猜語音辨識會錯成什麼。

分類是**一支影片一次批次呼叫**，不是每個候選各一次。經 Claude Code CLI 呼叫的單次成本約 0.10 美元（每次都載入其系統提示），直接呼叫 API 則約 0.003 美元；因此用 API 金鑰而非 CLI。

## Considered Options

- **LLM 讀全片逐字稿選段**：有語意理解，但引入隨機性，且 30 分鐘逐字稿的輸入成本高。降級為 T3，只對少數候選做是非題。
- **視覺模型抽幀判斷**：對靜態圖表畫面幾乎無鑑別力，成本最高。
- **指示代詞密度啟發式**（`youtube-transcription/bin/find-drawing.mjs` 已驗證可行）：零成本、決定性，能找到「講者正在指畫面」的時段，但無法區分那是進場、持倉還是閒聊。保留為其他類別的定位策略分支。
- **整句精確比對**（`這筆進場`、`這筆止損`）：**實測全滅**，見下。

## Consequences

- **不能假設講者會逐字照唸。** 三支自錄樣本（2:05 / 1:53 / 10:00）實測：整句精確比對 `這筆進場`／`這筆止損` 命中 **0/2**——一次因為講者插入了「就是」（「那這筆**就是**進場」），一次因為 Whisper 吐出簡體「损」。改用「前綴 + 5 字內事件詞」後 **2 真 0 假，全對**。
- **準確度預算全花在前綴上。** 「這筆」在 145 支同題材影片、231,715 個 segment 中僅出現 1 次，在自錄樣本中 recall 100%、precision 67%（誤報為「這筆方向就做錯了」）。誤報由分類器過濾掉，成本只是一次判定；漏偵測則無從察覺，且分類器再聰明也救不回來。
- **逐字稿必須先正規化再比對**：繁簡轉換、全形半形、英文大小寫。全部樣本 2154 字中真正的簡體只有 2 個，但**兩個都是「损」，剛好落在出場口令上**。低頻率、最大殺傷。
- **術語校正表仍然保留，但用途不同。** 它不再是比對用的白名單，只用來修正燒進字幕的錯字（`FVG` → `FBG`、`小肥波`）——那是呈現問題，不是定位問題。
- **比對必須在拼接後的全文上做，再反查時間碼**，不能逐 segment 比對。Whisper 的 segment 邊界是語音停頓，同一句口令會被切開。
- **不能用交易術語本身定位。** 講者在進場當下就會講「止盈就止損放在這個下緣」——設定 TP/SL 是進場動作的一部分。單獨的「進場」在語料中命中 537 次，絕大多數是講解（「如果實體跌破就不進場了」「有人想要在這邊進場也是有可能的」）。前綴不是優化，是必要條件。
