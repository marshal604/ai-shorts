# 事件由來源準備階段標記，字串比對降為交叉檢查

同類工具（AlphaCut、Opus Clip 及其開源仿作）都用模型從整支長影片「猜」哪裡是重點，這在交易分析影片上失效——價值不在「講得好的話」，而在「講的話正對著的那張圖」，而畫面是無人臉的螢幕錄影，人臉追蹤與語意選段都抓不到。我們改為讓講者在錄影當下口頭標記事件，系統從語音定位，再把取材範圍限縮在錨點附近。

事件的判定放在**來源準備階段**：該階段本來就要讀完整份逐字稿來校正同音錯字與專有名詞，讓它順便標記事件的邊際成本是零。前綴字串比對保留為**交叉檢查**——兩者不一致時提出來讓使用者看，而不是任一方單獨決定。

## 這個決定的演變

初版把準確度預算全押在字串比對上，理由是「把整份逐字稿餵給模型太貴、而且有隨機性」。三件事推翻了它：

1. **前綴自己會被聽錯。** 實測「這筆進場」被轉成「這比進場」（同音 zhè bǐ）。押注在「前綴不會錯」的前提不成立。
2. **語音辨識需要校正，而校正本來就要讀完整份逐字稿。** 成本論證失效——標記是搭便車。
3. **固定口令對講者是負擔。** 三支自錄樣本中，約定的口令沒有一次被逐字照喊。放寬成「依語意標記」之後，「現在進場」「我進了」都算數。

隨機性的顧慮由磁碟快取解決：回應以輸入雜湊為 key，同一支長影片重跑不再發出請求，結果完全可重現。

## Considered Options

- **純字串比對**（初版）：決定性、免費，但被同音錯字擊穿，且要求講者逐字照喊。降為交叉檢查。
- **字串比對抓候選、模型逐一分類**（第二版）：仍受限於前綴的召回。實測十三分鐘樣本中，模型把真正的進場宣告判成「在描述設置」而否決掉——分類器讀到的是被前綴切出來的片段，缺少足夠脈絡。
- **視覺模型抽幀判斷**：對靜態圖表畫面幾乎無鑑別力，成本最高。
- **指示代詞密度啟發式**（`youtube-transcription/bin/find-drawing.mjs` 已驗證可行）：零成本、決定性，能找到「講者正在指畫面」的時段，但無法區分那是進場、持倉還是閒聊。保留為其他類別的定位策略分支。

## Consequences

- **這仍然是一個錄影流程的約束**，只是寬鬆得多：講者必須在事件發生的當下**說出來**，但不必用固定句型。完全沒有宣告的影片不受理，不做降級處理。
- **逐字稿必須先正規化再比對**：繁簡轉換、全形半形、英文大小寫。全部樣本 2154 字中真正的簡體只有 2 個，但兩個都落在出場口令上——低頻率、最大殺傷。
- **不使用語音辨識的 initial prompt。** 曾用它餵術語表以提升專有名詞準確度，實測確實把 `FBG` 修成 `FVG`，但代價無法接受：同一份音檔（MD5 相同）各跑兩次，加了 prompt 會把 346 段壓成 68 段、吞掉 38 秒音訊、並把「這筆進場」改成「這比進場」。兩次結果位元級一致，是決定性因果而非運氣。專有名詞改在轉錄後校正。
- **校正只准動文字，不准動時間碼與段落數。** 時間碼是後面所有定位的依據。
- **收斂重複的錨點必須有時間窗。** 講者會把同一個事件連喊兩次，但只看「連續同角色」在偵測不完整時會把相隔數分鐘的兩筆交易的結束併成一個，兩筆一起消失——實測十三分鐘樣本正是如此。
- **偵測層的錯是無聲的**，這是本專案最危險的失敗模式。無法用任何方法消除，只能讓它現形：未配對的錨點與兩種訊號的不一致都寫進錨點文件，使用者一眼看得到「這裡少了一個」，而不是短片默默少一支。
- **不能用交易術語本身定位。** 講者在進場當下就會講「止盈就止損放在這個下緣」——設定停利停損是進場動作的一部分。單獨的「進場」在語料中命中 537 次，絕大多數是講解。
