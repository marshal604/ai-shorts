# 題材知識全部下放到 Category，引擎不認得交易

工具最初設定要支援多種題材（交易、美食、旅遊），但實際只有交易類別有素材可驗證。我們把題材知識——定位策略、骨架、構圖策略、術語表、長度目標——全部收進 `Category`，引擎只操作抽象概念（錨點、區段、骨架位置），完全不認得「進場」或「止盈」。v1 只實作交易一個類別；通用性放在型別裡，不放在實作裡。

Category 以 **TS 模組**撰寫（`categories/trading.ts`，`satisfies Category`），不用 JSON：弱訊號本質上是 RegExp（`/止[損损存]/`、`/TP\d.{0,6}(只贏|止盈)/`），塞進 JSON 會退化成脆弱的字串，而型別檢查能在編譯期擋掉寫壞的 preset。這是個人工具，沒有非工程師編輯 preset 的需求。

## Considered Options

- **不抽象，直接寫死交易邏輯**：最省事，但使用者明確要求三個軸（口令、類別、素材）都通用。
- **現在就實作多種定位策略**（口令／指示代詞密度／LLM 掃描）：真正通用，但等於同時做三個沒有需求的東西，而且沒有素材可以驗證它們對不對。改為把 `Locator` 定義成可辨識聯集，目前只有 `kind: 'cue'` 一個成員；日後新增是純增量，不動既有程式。
- **現在就做第二個類別來驗證抽象**：能真正檢驗介面抽對了沒，但使用者選擇先做交易。

## Consequences

- **骨架位置引用錨點的相對窗口，不引用題材概念。** `{ id: 'hook', source: { anchor: 'close', from: -8, to: 0 }, framing: 'roi', audio: 'mute' }`——引擎不知道 `close` 代表止盈還是止損。
- **骨架位置必須可塌縮。** 實測 10 分鐘樣本的一筆交易只持倉 20 秒，持倉快轉位置無素材可用。素材不足時位置消失、骨架縮短，不報錯。
- **「通用」在 v1 是承諾而非已驗證的事實。** 只有一個實例的抽象通常是錯的抽象；第一次加入第二個類別時，介面預期需要修改。這是刻意接受的代價，記錄於此以免未來讀者誤以為介面已經過驗證。
- 構圖策略（見 ADR-0003）同樣是 Category 欄位。內容感知裁切本身不綁定 TradingView——它是純像素分析，對任何螢幕錄影都成立；只有「把價格軸接到 K 線右緣」這個重組規則是交易類別特有的。
